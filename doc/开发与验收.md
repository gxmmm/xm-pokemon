# 开发与验收

先读 `PROJECT_RULES.md`、`README.md` 和 `当前美术规范.md`。每阶段完成开发、相关测试、产品验收和本地 Git 提交；推送与部署单独按用户指令执行。

## 低负载执行

检查与构建统一经过 `scripts/run.mjs`，同项目跨进程排队。Windows 使用低优先级、最多 2 个逻辑核心；浏览器批次结束后关闭实例，休息 3 秒再继续。不要同时启动多组重验证，也不要边跑浏览器边改前端源码。

完整战斗分为主体与异常/接触两批；场景截图按桌面尺寸分三批。取消只清理本次验证的进程树。总报告要求同一运行编号且批次完整成功。

## 产品验收要求

- 桌面 1366×768、1440×900、1920×1080：画布随窗口更新、只有一个实例、四边连续；菜单、HUD、入口和主要动作区可用。
- PMD 角色动作连贯、脚点稳定、转向不压成细线、弹体从正确挂点发出；正式入口过场至少1秒，资源齐备才开始，10秒未就绪提示网络异常并返回原入口。等待与取消不能改变战斗结果或存档。
- 命中、扣血、异常、控制解除和倒下保持同步；自然结算等待演出结束，经验和捕捉不重复结算。
- 多人混战保留目标轮廓和异常标记；多人镜头请求合并，结束回到全景；普通连续受击不打断施法，真实中断清除蓄力。
- 世界建筑与立柱有承托，水岸和岩面有厚度与层次，入口和路径对应真实地图；美术清理不改动地图、碰撞或战斗数值。
- 退出后画布、计时、帧任务、观察器和特效正常释放，控制台无错误。

## 产物管理

截图、候选图、报告和临时编译文件不提交 Git，可在不运行验证时清理。产物目录为 `doc/visual-baselines/`；删除后先生成新证据，不把缺失基线当作通过。

完整战斗以本次 `battle/suite-report.json` 为准。浏览器使用独立 Chrome 和隔离数据；SwiftShader 用于功能与画面回归，不能充当原生 GPU 性能结论。截图抽验与全量结构校验分别报告，不宣称逐帧穷举全部角色。

## 战斗空间回归

使用 `node scripts/run.mjs battle-space-report` 串行验证近战、混合、远程与围攻 12 场固定种子对局、完整复现、各性格优势距离、连续脚点跨界、闪避与特性免疫附加效果。近战成员必须都有输出，远程不能因残血目标坍缩为贴脸追击。

使用 `node scripts/run.mjs battle-browser-report --spacing-only` 检查 1366/1920 桌面实际站位、1440 桌面喷火龙蓄力/释放/打断。范围指示随快照移除，火焰终点遵守七格射程，分辨率不得改变战斗事实。

## 基础招式、速度与治疗

`node scripts/run.mjs battle-tempo-report`：151 物种基础招式与四配招分离；相同角色速度 20/80/200/极端值的实际释放数；基础与战术 CD 的不同收益、阶段/麻痹、动作占用与停步；友疗/自疗/满血/死亡/远距目标；高速远程仍能被近战接敌；种子 47 的混合治疗与三治疗阵容必须自然结束。

`node scripts/run.mjs battle-browser-report --tempo-only`：1440×900 串行检查喷火龙、怪力、皮卡丘、胡地、吉利蛋连续六秒出招，记录动作队列，截图起手/释放/衔接，HUD 只显示基础及战术招式与实际冷却秒数。

治疗量使用施法者有效攻击与 healingPower，不按受疗者最大生命放大；持续回复按攻击换算，满血不累计回复储备。基础冷却约 2–3.2 秒，速度分别通过基础/战术曲线缩短，统一出招占用限制实际最高频率，CD 增益变化保留已完成进度。

## 队伍协作

`node scripts/run.mjs battle-cooperation-report`：有效缺血、承压优先、双基础治疗实际分工、施法预约失效与重伤合救、保护目标不被粘性/分流覆盖、远处威胁不追逐、叠加控制取最长时长与控制窗口选敌。同时运行 tempo、space、smoke，确认续航残局收束、作战距离和动作占用保持有效。

协作参数位于 `packages/config/src/battle-cooperation.ts`。治疗预约只统计已经开始且即将完成的有效施法；即时治疗由真实血量更新协调。支援者天生攻击优先远程，避免只能近身进攻而在后排永久等待。协作评分不提供额外伤害或治疗加成。
