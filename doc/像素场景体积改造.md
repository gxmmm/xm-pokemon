# 像素场景体积改造

本轮按开发者要求保留像素风，并为世界与战斗背景补充 2.5D 体积。所有构件由 Pixi 绘制，不依赖 AI 背景图片。

## 场景变化

- 雾湾镇：屋顶瓦面、厚檐、侧墙、凹窗、门阶、灯塔及接地投影；岸边木栈道有板纹、钉点和支撑。大陆连续延伸，外围建筑不悬空。
- 幻境之塔五层：共享实际地图格，分别使用苔石、潮湿石材、灰蓝岩石与紫晶、炉台、星辉柱。墙顶、立面、外台形成连续承托。
- 五种战斗背景：林沿岩台、天然断层洞壁、深浅错落的潮滩、遗迹晶柱与竞技场看台。中央维持低对比地面，场景物件主要布置在边缘。
- 世界高物件与角色按照脚点排序，实际入口和台阶对齐。地图、碰撞、遭遇与战斗引擎规则未修改。

## 实现与回归

`PixelDiorama` 提供有限色阶、左上受光的材质构件；`WorldRelief` 消费配置所引用的真实地图格；`BattleRelief` 按环境配置绘制地形。地图格签名纳入世界配置基线，高物件分层计入静态预算，场景切换销毁旧层。

- `npm run typecheck`、`npm run smoke`、`npm run build`：本轮场景代码通过。
- `npm run visuals:battle -- --relief-only`：六张世界地图 × 三尺寸、五种战斗背景 × 三尺寸，共 33 张实际 renderer 截图，通过满窗口、画布数量、地图数据不变和预算检查。
- `npm run playable:browser`：正式世界/战斗 HUD、桌面缩放、菜单、自然结算与返回等通过，控制台错误为零。
- 产品两轮目视抽验通过，关闭悬浮建筑/孤柱、水面色条和洞壁重复尖角问题。复核了正式 HUD 与入口、主路、中央战区的关系。

截图与机器报告保存在忽略目录 `doc/visual-baselines`。本轮为像素构件的体积与层次升级，未替换玩家人物素材。

## 验证负载调整

开发者反馈软件渲染令电脑卡顿后，暂停正在执行的完整战斗回归，保留已经通过的结果。随后为检查与构建加入跨进程串行调度，Windows 低优先级、最多 2 个逻辑核心，并将战斗与场景图检查拆分为独立浏览器批次，批间休息 3 秒。

串行锁由系统监听端口持有，进程退出即释放；取消只处理本次启动的进程树，并等待清理完成后放行下一个检查。批次报告带同次运行编号，全部成功才生成通过的总报告。所有截图与断言保留。

调整后再次通过类型检查及三个轻量调度测试；完整 `npm run visuals:battle` 已按低优先级、最多 2 核分两批通过。覆盖六轮挂载/重开/退出、十五次环境切换、60 秒持续观察、动作/命中/控制同步、密集 3v3、五种地形边缘及全部异常/脚部检查。两批总报告 `suite-report.json` 为通过，浏览器错误为零，预热后堆增长约 0.67 MiB。该结果验证功能与释放，不代表原生 GPU 性能基准。
