# 当前美术规范

这是后续美术开发的唯一规范，配合 `PROJECT_RULES.md` 使用。工作树仅维护当前方案，历史实现按需查 Git。

## 统一风格

- 角色采用 PMDCollab 原生像素动作；世界、战斗背景及所有特效采用相同像素风。
- 场景用顶面、前立面、侧面、左上受光、接地阴影和遮挡建立 2.5D 体积，使用 Pixi 构件绘制。
- 仅桌面端，全窗口连续背景；角色保持比例，HUD 悬浮且文字清晰。输出像素网格为 2 CSS 像素。
- 全作只有一套视觉和镜头标准。异常表现为身体多处小火苗、紫烟、短电弧、局部冰晶及头顶标记，不使用身体装饰环。

## 发布素材与重建

- `apps/web/public/sprites/pmd-v1/`：151 只，每只正反图集、JSON、正反静态图标、`credits.txt`、`source.json`。
- 根目录保留上游许可证、README、贡献者名单与导入报告；这些是当前来源证据，不是开发计划。
- 固定上游版本：`1f201ba3f969dd0eb4447744dffaeaaef26f5ae7`，来源为 [PMDCollab/SpriteCollab](https://github.com/PMDCollab/SpriteCollab/tree/1f201ba3f969dd0eb4447744dffaeaaef26f5ae7)。具体权利和作者以随附记录为准。
- 界面精灵球仍使用 `sprites/icons/pokeball.png`，来源记录在同目录 `CREDITS.md`。
- 发布素材提交 Git，正常安装不用重新下载。`npm run assets:check` 检查引用、文件及署名完整性，并拒绝未登记的公共文件。
- 需要重建时运行 `npm run assets:rebuild`，要求 Python 和 Pillow；也可 `python scripts/import-pmd-battle-assets.py --species 35,36` 重建指定角色。原始下载缓存为忽略目录 `art-source/pmd-source-v1`。

## 动作与挂点

Idle、Walk、Attack、Hurt 全量可用。149 只使用 Shoot 或源别名施法，皮皮与皮可西采用 Dance 并保留。28 只有源 Faint，其余使用 Hurt 加统一淡出兜底。

正面采用源第 7 方向，背面第 3 方向；逐帧以 Shadow 原点对齐，保留头、身和手部标记。源时长单位为 1/60 秒，转换后仍保留相对时长；HitFrame／ReturnFrame 用于准备、释放与收招。持续施法可保持末帧。`authoredFrames` 使用原生姿态，不额外拉伸整图或叠加前冲。

嘴部标记部分仍由头点加偏移近似。151 只已经完成结构校验，但未逐只逐帧人工精修；后续按代表角色与体型分批改进。
喷火龙、拉普拉斯、快龙的 Shoot 出口使用 `scripts/pmd-anchor-calibration.json` 中经源帧对照的方向偏移，跟随逐帧头点；校准记录随 `source.json` 发布。`--anchors-only` 重建只写挂点及来源，并检查动作、尺寸和时长不变。电击与电链使用身体挂点；持续束流跟随出口，已发射弹体保留出生位置。水箭龟与耿鬼仍使用源头点近似，不能视为全量嘴部精修完成。
转向保留当前动作时钟、可见帧和稳定尺寸基准，新方向就绪后接续播放。动作跨帧切换保留剩余时间；完整 Attack 已包含返回姿态，其恢复阶段由 profile 的 `recoverySources` 选择 Idle，施法仍使用源 ReturnFrame 尾段，恢复时长不变。

## 配置入口

| 内容 | 位置 |
|---|---|
| 素材来源、manifest、角色表现、挂点、动作 | `packages/config/src/battle-art.ts`、`battle-pmd.ts` |
| 生成的帧尺寸 | `packages/config/src/pmd-battle.generated.ts` |
| 技能表现配方与预算 | `skill-visuals.ts`、`visuals.ts` |
| 身体异常与脚部接触 | `visuals.ts` 中的 `BATTLE_BODY_EFFECTS`、`BATTLE_FOOT_CONTACT` |
| 战斗环境与镜头 | `battle-environments.ts` |
| 世界场景与真实地图格 | `visuals.ts`、`maps.ts` |
| 像素体积构件 | `packages/renderer-pixi/src/PixelDiorama.ts`、`WorldRelief.ts`、`BattleRelief.ts` |

技能只保留一份玩法与通用视觉定义。角色差异通过 profile、theme、挂点与变体表达，renderer/Vue 不按物种、技能或资源路径写分支。

## 场景与战斗边界
正式入口以全局像素过场覆盖页面切换和资源加载，最少 1 秒、最多 10 秒。双方正反图集、必要动作和图标齐备后才推进模拟；超时提示网络异常并返回原入口。过场没有跳过、重试或确认操作。角色在覆盖层下可初始化，但不采用边加载边战斗的正式流程。

世界地面读取真实地图格；高物件按脚点与角色排序，台阶和入口对齐。五层塔分别为苔石、潮湿石材、灰蓝紫晶、炉台、星辉柱。建筑和立柱必须有连续地面承托。

五种战斗地形保留清楚的中央交战区，边缘物件负责前后层次。脚部草叶、脚步和地面反应位于角色下方或角色自身接触层；飞行、悬浮和倒下不生成草叶。允许自然局部交叠，不能完全吞没小体型主要轮廓。

`BattleSim → presentation → renderer DTO` 分层保持不变：玩法、移动、伤害和控制由引擎决定；动作和特效不得改写结算时机。命中、血量、状态和倒下演出按同一结果队列对齐；持续技能跟随挂点，已发射弹体保留发射位置。普通受击不能覆盖攻击或无限延长受击动作。

正式遇敌过场采用原场景短促震动、黑幕阶梯收拢、中央方形准星锁定、资源就绪后中心裂口展开至全窗口。仅展开结束才启动模拟；总过场保持1–10秒，临界就绪压缩展开，禁止用新的全屏等待卡片替代此节奏。
