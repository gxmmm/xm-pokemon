# 战斗 HUD 信息布局验收

日期：2026-09-07。

## 范围与交付

本轮聚焦桌面战斗信息，沿用全窗口场景与唯一视觉标准。引擎规则、移动阵位、镜头投影、技能数值与结算逻辑保持原有实现。

- 两侧共用 `BattleCombatantCard`，固定显示身份、生命数字及血条、当前行动、异常与技能。三只队伍的卡片高度一致，施法、控制、异常解除及倒下不会推移相邻卡片。中央至少保留半屏动作区域。
- 姓名为 14px，主要信息及技能名称为 12px，次级冷却数字为 11px。长名称省略后可悬停查看全文；技能在冷却期间仍显示名称和剩余秒数，普攻固定在末行。
- 生命不高于 20% 时显示“濒危”。施法显示技能名称、百分比及进度条；倒下后清除濒危、施法、异常和就绪强调。
- 眩晕独立于其他异常显示。眩晕、睡眠、冰冻提示“暂时无法行动”；麻痹、混乱只显示异常本身，不把概率性阻碍写成持续无法行动。
- 被打断提示保留约 0.9 秒，新施法事件立即清除旧提示。提示使用实际已展示的事件；冷却、血量、施法和眩晕时长使用与画面相同的 presentation 数据和时钟，保留原有 HUD 12fps 采样及生命/控制事件同步。
- 身体状态效果与头顶标识分开：燃烧保留小火苗，中毒/麻痹/冰冻保留身体细节，同时可以显示眩晕星标；睡眠/混乱与眩晕并存时头顶优先显示眩晕，HUD 保留完整组合。清除眩晕不影响仍存在的身体异常，倒下清理全部状态几何。
- 悬停目标按配置区分自身、敌方单体、敌方全体。伤害技能附带自身增益或减益时仍标为攻击敌人，不误分类为自身技能。

## 验证

- `npm run typecheck`、`npm run smoke`、`npm run build` 已通过。
- 新增 HUD 逻辑测试覆盖 20% 边界、显示时钟落后于引擎时的眩晕、概率异常语义、打断、倒下清理，以及自身/单体/范围技能目标说明。状态几何测试验证火苗和星标并存、眩晕解除只清星标、倒下清空。
- `npm run playable:browser` 已通过，报告于北京时间 22:48 更新，`passed=true`、`pageErrors=[]`。覆盖 HUD 专项，以及三尺寸全窗口、倍速、暂停恢复、跳过、自然结算、捕捉/放生/败北返回、回满、连点不重复结算及外部页面操作。
- HUD 专项使用真实战斗路由和隔离测试存档，覆盖 1366×768、1440×900、1920×1080、六只同时上场、长昵称、四技能、濒危施法、异常叠加、打断出现及消失、倒下、暂停冻结与解除状态后不跳位。可用 `npm run playable:browser -- --hud-only` 单独运行。
- `npm run visuals:battle -- --natural-only` 已通过，检查范围特效、脚部接触、异常解除/倒下及六种异常叠加眩晕；叠加样本在 80/300/650ms 留图，并断言六只头顶状态均为眩晕。
- 本轮首次接入 HUD 测试时改变了后续世界移动测试的起点，导致原本限定城镇的左移断言超时。已将城镇检查保留在原先顺序，HUD 测试随后独立进入隔离战斗；最终完整回归通过，未放宽生产行为断言。

## 产品验收与证据
